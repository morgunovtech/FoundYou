### 2. Street View только при наличии покрытия

## Известные ограничения на реальных фото

- `GPSImgDirection` пишут в основном iPhone; без него схема показывает только позицию и солнце.
- Сторона камеры по `LensModel`; Samsung иногда его не пишет → «какая камера, неизвестно».
- Угол обзора по `FocalLengthIn35mmFormat`; без него 70° (75° для фронтальной).
- Момент съёмки по цепочке доверия: `OffsetTimeOriginal` → GPS-время (`GPSDateStamp` + `GPSTimeStamp`, если не дальше 26 ч от настенных часов) → пояс места (из ответа погоды, только при включённом контексте) → долгота, приблизительно. Источник подписан в строке «Солнце».
- «Солнце под горизонтом» при дневном снимке означает неверное время или место; это проверка, не баг.
- Рельеф из Copernicus GLO-90 (ячейка 90 м); в горах ячейка может отличаться от точки на десятки метров, полоса ±30 м считается «на уровне земли».
- Координаты в запросах округляются до 4 знаков (~11 м); кэш ответов по ячейке.
- Ответы погоды, закэшированные до добавления `weather_code`, живут до суток; UI откатывается на облачность.

## Инструменты

- `scripts/make-exif-fixture.mjs`: вписывает EXIF (GPS, высота, точность, направление, скорость, GPS-время, дата, смещение, устройство, объектив, фокусное) в любой JPEG. Так проверялась карточка «Как был сделан снимок» без реального снимка. Пример: `node scripts/make-exif-fixture.mjs in.jpg out.jpg --lat 41.36123 --lon 69.92395 --alt 1287 --heading 312 --speed 0.4 --offset +03:00`.
- Проверка UI в песочнице делалась Playwright-скриптами с подменой `/api/*` через `page.route` и JPEG из canvas; они не в репозитории. Если понадобится smoke в CI, разумно вынести это в `scripts/smoke.mjs` с `playwright-core` и `PLAYWRIGHT_BROWSERS_PATH`.
