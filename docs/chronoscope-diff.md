# Chronoscope → Meta Data Insight: что перенесено, что потеряно

Сопоставление функциональности с проектом-предшественником **EXIF Risk Inspector** (рабочее имя `chronoscope`), написанным в ноябре 2025. Meta Data Insight решает ту же задачу — оценка приватности фотографии перед публикацией — но был написан заново, а не форком.

Документ составлен 2026-08-26 сравнением исходников обоих проектов, чтобы chronoscope можно было убрать с диска, не потеряв идей.

**Где теперь код chronoscope:** [github.com/morgunovtech/chronoscope](https://github.com/morgunovtech/chronoscope) (приватный). До 2026-08-26 весь его исходник лежал вне git — под версионным контролем был только README. Локальная копия удалена.

---

## Коротко

Meta Data Insight сильнее во всём, что касается **очистки** снимка и **глубины разбора метаданных**. Chronoscope был сильнее в **контекстной реконструкции** — он пытался восстановить обстоятельства съёмки, а не только показать риск.

Из chronoscope не перенесены четыре вещи. Одна из них — заглушка, одна почти бесполезна, две реально стоят портирования.

---

## Что было в chronoscope и чего нет в meta-data

### 1. OCR — распознавание текста на снимке ⭐ стоит перенести

`src/components/analysis/OCRAnalysis.ts` — Tesseract.js, подгружался динамическим импортом.

Зачем это в контексте приватности: на фото попадают таблички с адресами, бейджи, экраны с почтой, номера машин, номера палат, ценники с названием магазина. EXIF можно вычистить, а текст на самой картинке остаётся — и он индексируется поиском по изображениям.

Важно, что в chronoscope OCR был не самоцелью, а входом для очистки: результат распознавания шёл в `blurOCR()` — размывались именно те области, где нашёлся текст. В meta-data есть ручные маски-кисти, но пользователь должен сам заметить текст. Автоматическая подсветка «вот здесь читаемый текст» — это то, чего сейчас не хватает.

> В `src/i18n/index.tsx` есть ключ `introFeatureOcr`, но его значение — «Process photos locally — nothing is sent to external servers». Ключ остался от планов на OCR, к распознаванию отношения не имеет. При портировании стоит переименовать, чтобы не путать.

### 2. Детекция праздников ⭐ стоит перенести

`functions/api/holiday.ts` — обращение к [Nager.Date](https://date.nager.at) по дате съёмки и коду страны.

Идея тоньше, чем кажется. Приватный риск даёт не сама дата, а её сочетание с местом: «снято 31 декабря по этому адресу» — сильный сигнал о том, где человек проводит праздники, то есть где живёт его семья и где его не будет в другие дни. Для сталкинга и для планирования кражи это разные, но одинаково полезные данные.

Портирование дешёвое: код страны уже приходит из обратного геокодирования (Nominatim), дата — из EXIF. Функция маленькая, но её надо переписать под `functions/api/_shared.ts` — оригинал не проверяет Origin, не ставит таймаут на upstream и не кэширует.

### 3. Offline-режим через service worker — на любителя

`public/sw.js`, 25 строк — кэширование статики.

Реальной пользы мало: приложение и так работает локально после загрузки, а офлайн-запуск нужен редко. При этом service worker добавляет проблем с инвалидацией кэша при деплое. Переносить только если появится запрос на PWA-установку.

### 4. «Анализ скрытых слоёв» — заглушка, переносить нечего

`src/components/analysis/LayersAnalysis.ts` заявлял разбор контейнера: встроенные превью, XMP, ICC, сегменты APP1/APP13. Фактически он не парсил ничего:

```ts
const hasXMP = true;  // Assume XMP might be present
const hasICC = true;  // Assume ICC might be present
```

Значения захардкожены или выведены из одного лишь MIME-типа. Это макет интерфейса, а не функция.

Показательно, что meta-data закрывает ту же задачу по-настоящему: `exifr` реально извлекает XMP, IPTC и ICC и показывает то, что нашлось. Идея была верной, реализация — нет; в meta-data она уже воплощена.

## Что есть в meta-data и никогда не было в chronoscope

| Возможность | Комментарий |
|---|---|
| **HEIC** | `src/utils/heic.ts` + heic2any. Chronoscope принимал только JPEG/PNG/WebP — то есть не открывал то, что снимает айфон по умолчанию. |
| **XMP / IPTC / ICC** | Реальное извлечение через exifr. Chronoscope ограничивался EXIF + GPS. |
| **Ослабление PRNU** | Шум матрицы — отпечаток конкретного экземпляра камеры, по нему снимки связываются между собой. В chronoscope не было ничего подобного. |
| **Ручные маски-кисти** | Дорисовать закрашивание там, где автоматика не сработала. |
| **«Анти-поиск»** | Микрокроп, поворот, шум, сдвиг цвета — против поиска по изображению. |
| **Водяной знак, нейтральное имя файла, выбор качества JPEG** | Chronoscope умел только «скачать очищенное». |
| **Обвязка API** | `functions/api/_shared.ts`: валидация координат, таймаут upstream 10 с, кэширование, проверка Origin, единый формат `{ ok, data \| error }`. В chronoscope каждая функция ходила в upstream напрямую, без этого. |
| **Проверки качества** | typecheck, eslint, юнит-тесты утилит. У chronoscope был только один Playwright-спек (`tests/basic.spec.ts`). |

Очистка в chronoscope сводилась к трём функциям в `src/utils/cleanup.ts`: `removeMetadata()`, `blurFaces()`, `blurOCR()`. В meta-data это полноценный конвейер с настройками.

## Одинаковое в обоих

Обратное геокодирование (Nominatim), историческая погода (Open-Meteo Archive), POI поблизости и вероятные камеры (Overpass), карта, детекция объектов COCO-SSD, определение часового пояса по координатам, три языка (ru/en/uz), переключение тем, удаление метаданных через перекодирование canvas, размытие лиц по детекциям.

В chronoscope блок камер назывался `CamerasBlock`, в meta-data соответствующий эндпоинт — `surveillance-candidates`. Это одно и то же.

## Разница в архитектуре

| | chronoscope | meta-data |
|---|---|---|
| UI | lit-html, ручной рендер | React + hooks |
| Состояние | глобальное в `app.ts` | хуки (`useImageFile`, `useExifMetadata`, `useImageAnalysis`, `useAPIFetch`) |
| Модель COCO-SSD | базовая | `lite_mobilenet_v2` — заметно легче |
| Тесты | 1 Playwright-спек | typecheck + eslint + юнит-тесты утилит |
| Ошибки | без выделенной обработки | `ErrorBoundary` + `ErrorBanner` |

Переход на React был оправдан: в chronoscope состояние размазано по модулю `app.ts`, и добавление шага очистки требовало правок в нескольких местах.

---

## Итог

Стоит завести задачи на **OCR с автоматическим размытием найденного текста** и **детекцию праздников** — обе идеи рабочие и в текущем meta-data не покрыты. Service worker — по желанию. Анализ слоёв — закрыт, meta-data делает это лучше через exifr.
