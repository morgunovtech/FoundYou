# Chronoscope → Meta Data Insight: что перенесено, что потеряно

Сопоставление функциональности с проектом-предшественником **EXIF Risk Inspector** (рабочее имя `chronoscope`), написанным в ноябре 2025. Meta Data Insight решает ту же задачу — оценка приватности фотографии перед публикацией — но был написан заново, а не форком.

Документ составлен 2026-08-26 сравнением исходников: chronoscope @ `160453a` против meta-data @ `main` (`45261f7`), чтобы chronoscope можно было убрать с диска, не потеряв идей.

**Где теперь код chronoscope:** [github.com/morgunovtech/chronoscope](https://github.com/morgunovtech/chronoscope) (приватный). До 2026-08-26 весь его исходник лежал вне git — под версионным контролем был только README. Локальная копия удалена.

---

## Коротко

Meta Data Insight перекрывает chronoscope практически полностью. Из уникального у предшественника осталось **две вещи**: детекция праздников (стоит перенести) и offline-режим (на любителя). Ещё одна — «анализ скрытых слоёв» — оказалась заглушкой без реализации.

Отдельно стоит **автоматическое размытие областей с распознанным текстом**: OCR в meta-data сильнее, чем был в chronoscope, но связка «нашли текст → сами замазали» у предшественника была, а здесь пользователю показывают подсказку и оставляют замазывать вручную.

---

## Что было в chronoscope и чего нет в meta-data

### 1. Детекция праздников ⭐ стоит перенести

`functions/api/holiday.ts` — обращение к [Nager.Date](https://date.nager.at) по дате съёмки и коду страны. На `main` ничего похожего нет.

Идея тоньше, чем кажется. Приватный риск даёт не сама дата, а её сочетание с местом: «снято 31 декабря по этому адресу» — сильный сигнал о том, где человек проводит праздники, то есть где живёт его семья и где его не будет в остальные дни.

Портирование дешёвое: код страны уже приходит из обратного геокодирования, дата — из EXIF. Но переписывать надо под текущие конвенции `functions/api/` — оригинал не проверяет Origin, не ставит таймаут на upstream и не кэширует ответ.

### 2. Автоматическое размытие текста, найденного OCR ⭐ стоит перенести

Не целиком OCR — он здесь уже есть и лучше (см. ниже), — а именно связка с очисткой.

В chronoscope результат распознавания шёл в `blurOCR()` (`src/utils/cleanup.ts`): размывались ровно те области, где нашёлся текст. В meta-data `OCRBlock.tsx` показывает подсказку `ocrBlurHint` — «Эти области можно замазать в разделе очистки» — и дальше пользователь рисует маски вручную.

Координаты распознанных блоков у нас уже есть, механизм масок тоже (`ManualMask` в `src/types/cleanup.ts`). Не хватает кнопки «замазать всё найденное»: превратить bounding-box'ы Tesseract в маски одним действием.

### 3. Offline-режим через service worker — на любителя

`public/sw.js`, 25 строк — кэширование статики. На `main` service worker отсутствует.

Реальной пользы мало: приложение и так считает всё локально после загрузки, а офлайн-запуск нужен редко. При этом SW добавляет проблем с инвалидацией кэша при деплое. Переносить только если появится запрос на PWA-установку.

### 4. «Анализ скрытых слоёв» — заглушка, переносить нечего

`src/components/analysis/LayersAnalysis.ts` заявлял разбор контейнера: встроенные превью, XMP, ICC, сегменты APP1/APP13. Фактически не парсил ничего:

```ts
const hasXMP = true;  // Assume XMP might be present
const hasICC = true;  // Assume ICC might be present
```

Значения захардкожены или выведены из одного лишь MIME-типа. Это макет интерфейса, а не функция.

Показательно, что meta-data закрывает ту же задачу по-настоящему: `exifr` реально извлекает XMP, IPTC и ICC и показывает то, что нашлось. Идея была верной, реализация — нет.

## Что есть в meta-data и никогда не было в chronoscope

| Возможность | Комментарий |
|---|---|
| **HEIC** | `src/utils/heic.ts`. Chronoscope принимал только JPEG/PNG/WebP — то есть не открывал то, что снимает айфон по умолчанию. |
| **XMP / IPTC / ICC** | Реальное извлечение через exifr. Chronoscope ограничивался EXIF + GPS. |
| **Ослабление PRNU** | Шум матрицы — отпечаток конкретного экземпляра камеры, по нему снимки связываются между собой. В chronoscope не было ничего подобного. |
| **Ручные маски-кисти** | `ManualMask` — дорисовать закрашивание там, где автоматика не сработала. |
| **«Анти-поиск»** | Микрокроп, поворот, шум, сдвиги яркости/контраста/насыщенности/оттенка, warp — против поиска по изображению. У chronoscope очистка сводилась к трём функциям: `removeMetadata()`, `blurFaces()`, `blurOCR()`. |
| **Водяной знак, выбор качества JPEG** | Chronoscope умел только «скачать очищенное». |
| **OCR мощнее** | `rus+eng` с предобработкой против однопроходного распознавания; ассеты Tesseract самохостятся (`npm run prepare:ocr` → `public/ocr/`), а не тянутся с CDN. |
| **Проверки качества** | eslint + vitest, 5 юнит-тестов утилит и 3 отдельных скрипта. У chronoscope был один Playwright-спек (`tests/basic.spec.ts`). |
| **Обработка ошибок** | `ErrorBoundary` + `ErrorBanner`. В chronoscope выделенной обработки не было. |

## Одинаковое в обоих

Обратное геокодирование (Nominatim), историческая погода (Open-Meteo Archive), POI поблизости и вероятные камеры (Overpass), карта, детекция объектов COCO-SSD, определение часового пояса по координатам, три языка (ru/en/uz), переключение тем, удаление метаданных через перекодирование canvas, размытие лиц по детекциям.

В chronoscope блок камер назывался `CamerasBlock`, здесь соответствующий эндпоинт — `surveillance-candidates`. Это одно и то же.

## Разница в архитектуре

| | chronoscope | meta-data |
|---|---|---|
| UI | lit-html, ручной рендер | React + hooks |
| Состояние | глобальное в `app.ts` | хуки (`useImageFile`, `useExifMetadata`, `useImageAnalysis`, `useOCR`, `useAPIFetch`) |
| Модель COCO-SSD | базовая | `lite_mobilenet_v2` — заметно легче |
| Тесты | 1 Playwright-спек | eslint + vitest |

Переход на React был оправдан: в chronoscope состояние размазано по модулю `app.ts`, и добавление шага очистки требовало правок в нескольких местах.

---

## Итог

Стоит завести две задачи: **детекция праздников** и **кнопка «замазать весь найденный текст»**. Service worker — по желанию. Анализ слоёв закрыт: meta-data делает это лучше через exifr.
