# ADR-0001: Декодирование HEIC и извлечение метаданных в браузере

**Status:** Accepted
**Date:** 2026-07-31 (решение реализовано 2026-03-30, коммиты `99dc174`, `2533475`, `512f349`)
**Deciders:** Semyon Morgunov

## Контекст

Meta Data Insight обрабатывает фотографии полностью на клиенте — это ключевое
продуктовое обещание («не передавая файл в сеть»). Большинство снимков с iPhone
приходят в формате HEIC/HEIF, и здесь возникают две независимые проблемы:

1. **Декодирование пикселей.** HEIC нативно декодируют только Safari 17+ и
   браузеры на macOS с системным кодеком. В Chrome/Firefox на Windows, Linux и
   Android файл не открывается вообще — а это большая часть аудитории.
2. **Извлечение метаданных.** Библиотека `exifr`, используемая для EXIF/XMP/IPTC/ICC,
   не умеет парсить контейнер ISO BMFF (HEIC), поэтому «в лоб» метаданные из
   HEIC не извлекаются — а именно метаданные и есть предмет анализа приложения.

Исторически использовалась библиотека `heic2any`: она распространяется как UMD-модуль,
что ломало dynamic import под Vite (коммит `f45c8dc` — обходной путь), базируется на
устаревшей сборке libheif и не декодировала часть современных вариантов HEIC
(10-битный HDR, multi-image с iPhone). Требовалось решение с полным покрытием
форматов, не раздувающее начальный бандл.

Ограничения:

- Никакой серверной конвертации — только браузер (приватность).
- Начальный бандл не должен вырасти: WASM-декодер весит мегабайты.
- Превью нужно быстро: у большинства пользователей Apple-устройств декодер уже
  есть в системе, заставлять их ждать WASM — расточительно.

## Решение

**Трёхуровневая цепочка декодирования** в [`src/utils/heic.ts`](../../src/utils/heic.ts)
(`decodeHeicToJpegForPreview`):

1. `createImageBitmap(file)` — нативный декодер (Safari 17+, Chrome на macOS).
2. `<img>` с object URL и таймаутом 5 с — системный кодек macOS, когда
   `createImageBitmap` HEIC не поддерживает.
3. `libheif-js` (WASM, актуальная сборка libheif) — универсальный fallback,
   загружается лениво через `import()` только когда нативные пути не сработали.

Результат любого уровня рисуется на canvas, масштабируется до 2200 px по большей
стороне и кодируется в JPEG (q=0.92) для дальнейшего пайплайна анализа.

**Извлечение метаданных — из оригинального файла, а не из перекодированного JPEG**
(`extractMetadataFromOriginal`): побайтовый поиск сигнатуры `Exif\x00\x00` + TIFF-заголовка
(`II`/`MM`) в контейнере HEIC, извлечение TIFF-блоба (до 64 КБ) и передача его в `exifr`.
Так метаданные не теряются при конвертации, а `exifr` работает с форматом, который
он действительно поддерживает.

## Рассмотренные варианты

### Вариант A: heic2any (статус-кво)

| Измерение | Оценка |
|-----------|--------|
| Сложность | Низкая (готовая библиотека) |
| Стоимость | ~1 МБ WASM, всегда в составе fallback |
| Покрытие форматов | Неполное: старая сборка libheif, падает на 10-bit HDR и multi-image HEIC |
| Знакомство команды | Уже использовалась |

**Плюсы:** минимум кода; уже интегрирована.
**Косы:** UMD-упаковка конфликтует с Vite/ESM; проект малоактивен; не декодирует часть реальных файлов с современных iPhone — то есть не решает задачу.

### Вариант B: только нативное декодирование (createImageBitmap / `<img>`)

| Измерение | Оценка |
|-----------|--------|
| Сложность | Низкая |
| Стоимость | Нулевая (0 байт в бандле) |
| Покрытие форматов | Только Safari 17+ и macOS-браузеры |
| Знакомство команды | Высокое |

**Плюсы:** бесплатно, быстро, аппаратное декодирование.
**Косы:** Windows/Linux/Android Chrome и Firefox остаются без HEIC вовсе — неприемлемо для веб-приложения общего пользования.

### Вариант C: только libheif-js (WASM)

| Измерение | Оценка |
|-----------|--------|
| Сложность | Средняя (ручной рендер через `display()` callback) |
| Стоимость | Несколько МБ WASM для каждого HEIC-пользователя, включая тех, у кого есть системный кодек |
| Покрытие форматов | Полное (актуальный libheif) |
| Знакомство команды | Новая зависимость |

**Плюсы:** один кодовый путь; предсказуемое поведение во всех браузерах.
**Косы:** пользователи Apple (основной источник HEIC!) платят загрузкой WASM и медленным программным декодированием там, где нативный путь мгновенен.

### Вариант D: нативно → libheif-js как ленивый fallback (выбран)

| Измерение | Оценка |
|-----------|--------|
| Сложность | Средняя/высокая (три пути + управление ресурсами) |
| Стоимость | 0 байт для Apple-пользователей; WASM грузится лениво только при необходимости |
| Покрытие форматов | Полное |
| Знакомство команды | Комбинация уже написанных путей |

**Плюсы:** быстрый путь там, где он есть; полное покрытие там, где его нет; WASM вне начального бандла.
**Косы:** три ветки кода, которые нужно тестировать; порядок фолбэков нужно поддерживать.

## Анализ компромиссов

- **Скорость vs универсальность.** Чистые варианты B и C жертвуют одним ради
  другого; каскад D платит за «и то и другое» сложностью кода. Это осознанная
  плата: HEIC-файлы приходят в основном с Apple-устройств, где нативный путь
  бесплатен, а WASM нужен именно «чужим» платформам.
- **Метаданные: конвертация vs оригинал.** Декодирование через canvas уничтожает
  EXIF, поэтому метаданные обязаны извлекаться из исходного файла. Побайтовый
  поиск TIFF-блоба — эвристика, но она проще и надёжнее полноценного парсера
  ISO BMFF (обход `meta`/`iinf`/`iloc` боксов) и покрывает реальные файлы
  iPhone/Android.
- **Лимит 64 КБ на TIFF-блоб** — компромисс между простотой и полнотой: покрывает
  практически любой EXIF, но теоретически может обрезать гигантские maker notes.

## Последствия

Стало проще:

- HEIC работает во всех основных браузерах, включая Windows/Android Chrome и Firefox.
- Пользователи Safari/macOS получают мгновенное превью без загрузки WASM.
- Начальный бандл не вырос: `libheif-js` подключается динамическим импортом.
- Метаданные HEIC извлекаются в том же пайплайне `exifr`, что и JPEG/PNG.

Стало сложнее:

- Три пути декодирования — матрица тестирования выросла (Safari, macOS Chrome, Windows Chrome, Firefox, Android).
- Побайтовый поиск `Exif\x00\x00` — эвристика: возможны ложные срабатывания на сигнатуру внутри произвольных данных и обрезка EXIF > 64 КБ.
- WASM-декодирование идёт в главном потоке — большие файлы могут подвешивать UI.
- Появилась зависимость от `libheif-js`, за версиями которой нужно следить (безопасность декодеров).

Придётся вернуться, если:

- `exifr` получит нативную поддержку HEIC — тогда эвристику извлечения TIFF можно удалить;
- Chrome/Firefox добавят нативное декодирование HEIC — тогда fallback станет мёртвым кодом;
- появятся жалобы на зависание UI — тогда уровень 3 нужно унести в Web Worker.
