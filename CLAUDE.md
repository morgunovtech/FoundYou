# CLAUDE.md — Found You (repo `meta-data`)

Guidance for Claude Code sessions in this repository. Product: https://foundyou.morgunov.tech/ — a browser-only photo privacy analyzer and cleaner. Read `README.md` for the full feature and privacy description; this file is about how to work in the code.

## Stack

- React + TypeScript SPA built with Vite; Cloudflare Pages for static hosting, Pages Functions (`functions/api/*.ts`) as the only server code. Exact dependency versions: `package.json` (do not hard-code them in docs).
- Browser-side engines: `exifr` (metadata), `@mediapipe/tasks-vision` (two FaceDetector passes — BlazeFace short range and full range — plus ObjectDetector EfficientDet-Lite2 with COCO labels for people/objects; WASM runtime and `.tflite` models self-hosted under `public/mediapipe`), `tesseract.js` (OCR, `rus+eng`, LSTM), `libheif-js` (HEIC fallback decoder), `maplibre-gl` (map, lazy-loaded and behind a button — see `components/MapBlock.tsx`).
- Node 22 (`.nvmrc`, `engines` in `package.json`). Tests: vitest. Lint: ESLint. Format: Prettier.

## Commands

```bash
npm ci
npm run prepare:assets   # copies Tesseract + MediaPipe WASM runtimes and the c2pa toolkit, downloads the .tflite models into public/ocr, public/mediapipe, public/c2pa (once)
npm run dev              # http://localhost:5173, /api/* served by functions/ via the Vite plugin
npm run lint
npm run typecheck        # tsc --noEmit over src, functions, vite.config.ts
npm test                 # vitest run — src/**/__tests__/*.test.ts
npm run build            # prepare:assets + typecheck + vite build → dist/
npm run smoke            # scripts/smoke.mjs: drives a running dev server (SMOKE_URL) in the local Chrome via playwright-core; /api/* is stubbed
node scripts/frame-calibration.mjs <dir>   # «Проверка кадра» bench: runs frameBlockData from the dev server over <dir>/edited и <dir>/untouched and prints the separability table
```

`prepare:assets` needs network access (storage.googleapis.com). The `.claude/launch.json` entry `vite-dev` starts the dev server for the browser preview.

## Conventions

**Design system (non-negotiable):** `border-radius: 0`; no `box-shadow`, gradients, emoji, or `font-weight: 700`; colours and type only from `--v4-*` tokens; sizes and gaps are literal px values (do not introduce `--space-*` or other token twins). DS component classes are `.v4-*`; every page-specific class is prefixed `.fy-` and lives in `src/styles.css`. Themes switch on `data-theme` on `<html>` (`light` implicit, `dark`, `high-contrast`); preference key `theme-preference`.

**i18n:** every user-facing string is a key in `messages.ru` with translations in `en` and `uz`; `MessageKey` is derived from the `ru` dictionary, so a missing key fails `typecheck`. Use `t('key', { param })`. Do not add `lang === 'ru' ? … : …` ternaries in new code (legacy ones remain in `heuristics/` and `sceneNarrative.ts`; convert when touching them). Hooks return machine codes (`DetectionErrorCode`, `OCRErrorCode`, stage ids) and never translated strings; components map codes to keys (see `*_KEYS` tables in `App.tsx`).

**Functions:** build each endpoint with `defineHandler` from `_geo.ts` (GET/HEAD only → 405, same-site check → 403, exceptions → 500 `internal-error`). Parse coordinates with `parseCoord`, round with `round4`/`coordKey`, call upstreams through `fetchUpstream` (shared `USER_AGENT`, 8 s timeout, no upstream error text to the client), cache with `withCache` using `cacheKey(name, …)`, respond with `json()` so every answer carries `nosniff`, `X-Robots-Tag: noindex` and correct `Cache-Control` (public only when `ok`). Body shape is `{ ok: true, data }` / `{ ok: false, error: '<kebab-code>' }`; statuses: 400 invalid input, 429 upstream rate limit, 502 upstream failure/invalid, 504 upstream timeout. `_headers` does not apply to Functions.

**Platforms (every feature, every time):** the two platforms this is used from are Android/Chrome and iOS/Safari, and they diverge where it matters most. When proposing or building anything that touches pixels, files or device APIs, say in the same breath how it behaves on both, and check the divergent path rather than assuming it: HEIC decodes natively in Safari but goes through `libheif-js` in Chromium; `canvas.toBlob` is ImageIO on Safari and libjpeg-turbo in Chromium, so any quality, dip or size number calibrated in one is not a fact about the other; `BarcodeDetector` exists in Chromium and not in Safari (jsQR fallback); a canvas past ~16 MP stops being drawable on an iPhone, which is what `utils/platform.ts` encodes; `navigator.share` with files behaves differently on iOS. A limit or a threshold that differs per platform belongs in `utils/platform.ts` with the measurement that justifies it written next to it. The sandbox has Chromium only — WebKit cannot be installed — so what cannot be verified here is stated as unverified, with a manual checklist against the branch preview on a real device.

**Frontend:** explanatory text goes in `Explainer` next to the data it explains and is always visible — never behind a toggle, badge or «Pro» switch (raw data tables may collapse, explanations may not); blob URLs are revoked when replaced; heavy libraries are `import()`-ed lazily; new sections go inside an `ErrorBoundary variant="inline"`; visible status text uses `role="status"`.

## Privacy invariants (do not break)

1. The image, its pixels, filename and full metadata never leave the device. No upload, no third-party fetch with image data.
2. Place context requests (`useGeoContext`) send only 4-decimal rounded coordinates plus the capture date/time (country code + date for holidays). They start automatically when EXIF has GPS, so the section must always show what was sent (`geoDisclosure`). The «Не запрашивать контекст места» switch and the `geo-context` preference were removed by the owner on 2026-09-16; if an opt-out ever returns it must stop every request and the map (OSM tiles) for all later photos. Adding any field to these requests is a privacy decision, not a feature. The map is the one place where the browser talks to a third party directly: maplibre fetches raster tiles from tile.openstreetmap.org, so OSM sees the reader's IP address and which tiles were asked for — roughly the place of the shot, unrounded, learned by someone who is not us. Since 2026-09-20 `MapBlock` therefore renders an `Explainer` and a button instead, and mounts the map (`MapCanvas`) only once that button is pressed; the state is per mount, so a new photo is a new decision. Measured in Chromium against a JPEG with GPS: zero requests to tile.openstreetmap.org before the press, four after. Nothing may mount the map automatically, and the tiles must never be cached on the device — a tile cache is a history of places.
3. Runtime assets (Tesseract worker/core/traineddata, MediaPipe WASM runtime and `.tflite` models, the c2pa worker and WASM) are self-hosted under `public/`; no CDN URLs at run time. Any new external host must also be added to the CSP in `public/_headers` — treat that as a privacy decision, not a config tweak.
4. Exported files are re-encoded through canvas and then passed through `stripContainerMetadata`. The one exception is the «Только метаданные» preset on a JPEG or PNG source (`losslessExport` in `App.tsx`): the original picture bytes are kept and only the container is rewritten — `stripContainerMetadata` walks the scans to the real end of the image and drops every metadata segment and anything after EOI / IEND (vendor trailers, Motion Photo). The "0 fields left" verification must stay literally true for JPEG and PNG on both paths.
5. No analytics, cookies, or fingerprinting; `localStorage` holds only `theme-preference` and `meta-data-lang`.
